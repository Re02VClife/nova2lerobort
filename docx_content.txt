9.4 从模式7  10 11 恢复到 5(enable)
conda run --no-capture-output -n nova2_lerobot python - <<'PY'
import re
import socket
import time
HOST = "192.168.5.1"
PORT = 29999
def send(sock, cmd):
    sock.sendall(cmd.encode("ascii"))
    time.sleep(0.5)
    reply = sock.recv(4096)
    print(cmd, repr(reply))
    if not reply:
        raise RuntimeError(f"{cmd} 收到空回复")
    return reply
def parse_mode(reply):
    text = reply.decode("utf-8", errors="replace")
    match = re.search(r"\{(\d+)\}", text)
    if not match:
        raise RuntimeError(f"无法解析RobotMode：{text!r}")
    return int(match.group(1))
with socket.create_connection((HOST, PORT), timeout=3) as sock:
    sock.settimeout(3)
    mode = parse_mode(send(sock, "RobotMode()"))
    if mode in (7, 10, 11):
        send(sock, "Stop()")
        time.sleep(1)
    send(sock, "ClearError()")
    mode = parse_mode(send(sock, "RobotMode()"))
    if mode in (1, 2, 3):
        send(sock, "PowerOn()")
        time.sleep(3)
        mode = parse_mode(send(sock, "RobotMode()"))
    if mode == 4:
        send(sock, "EnableRobot()")
        time.sleep(2)
    deadline = time.monotonic() + 10
    while True:
        mode = parse_mode(send(sock, "RobotMode()"))
        if mode == 5:
            break
        if time.monotonic() >= deadline:
            send(sock, "GetErrorID()")
            raise RuntimeError(f"未能恢复到模式5，当前模式={mode}")
        time.sleep(0.5)
    send(sock, "GetErrorID()")
    print("restore_mode5=PASS")
PY

13.录制流程
Recording episode 0 → 操作机械臂 → 按 A → 立即停止向数据集写入 → 显示 Reset the environment → 人工归位积木，此阶段不保存视频和动作 → 再按 A → 保存 episode 0 → 显示 Recording episode 1 → 开始下一条录制
遇到的问题:
1. 问题:原始夹爪标签使用稀疏事件语义-1/0/+1，其中绝大多数帧为0，导致模型倾向于一直输出接近0；
尝试解决方法:把夹爪的loss ✖5,看看训练效果
结果:不太行 用键盘录制数据太差了 换手柄试试
2..摄像头帧率30fps的情况下,机械臂帧率不能调30,会报错
报错原因是: 两台相机本身工作正常，没有丢帧或打开失败, 但640×480双相机读取已经占用了大部分循环预算, 问题属于端到端负载不足,具体为
每一帧里面需要做1. 读取机械臂关节角、TCP位姿和夹爪状态 2. 读取手柄输入 3. 读取手腕相机 4. 读取正面相机 5. 生成本轮动作 6. 发送ServoP指令 7. 组织状态、动作和两张图像 8. 将数据交给数据集写入器 9. 等待到下一帧
双相机读取已经占用了大部分时间预算，再叠加Nova2网络通信和数据处理，总耗时超过了50 ms
解决方法:cpu(cpu型号为Intel(R) Core(TM) i9-14900K)瓶颈了,这个没法提升,要么降分辨率为320×240,要么,就降低录制帧率为10fps
先试试分辨率为320*240的训练效果,如果效果不行只能降低帧率
后续:相机驱动写死了分辨率 没法降分辨率,降录制帧率到10数据集采集效果太差
新方法:增加两个参数, --dataset.num_image_writer_processes=2 --dataset.num_image_writer_threads_per_camera=2
将录制流程改为: 
主进程： 读取机器人和相机 → 发送ServoP → 构造帧 → 将图像任务交给后台写入器 → 尽快进入下一轮 
后台进程： 接收图像任务 → 并行处理图像 → 写入临时图像或缓存
即将接受和处理图像的任务和录制并运行机械臂解耦,缓解cpu压力
